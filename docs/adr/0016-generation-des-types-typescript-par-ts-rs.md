# ADR 0016 : Génération des types TypeScript par ts-rs

- **Statut** : accepté
- **Date** : 2026-10-18
- **Décideurs** : propriétaire du dépôt (AresGn)

## Contexte

Les types échangés entre le cœur Rust et l'interface Svelte sont **générés depuis Rust vers TypeScript, jamais écrits à la main** (design 0002 §6, décision du 2026-10-18 ; ADR 0010 : dossier `apps/desktop/ui/src/lib/generated/`), et la CI vérifie qu'ils sont à jour. Le crate de génération restait à choisir ; l'ajout d'une dépendance se demande d'abord (PRD §14). Ticket #27. Le type du message de progression (ADR 0015) est le premier type à générer.

**Vérifié (2026-10-18)**, détail et sources de l'essai dans `docs/research/2026-10-18-types-typescript.md` :
- `ts-rs` 12.0.1 (stable, publiée le 2026-01-31, licence MIT) : une union à balise (`#[serde(tag = "kind")]`) donne une union TypeScript correcte, un newtype avec `#[ts(type = "number")]` donne `number`, `Option<T>` donne `T | null`, un `u64` donne `bigint` par défaut (faux à l'exécution, `serde_json` produit un nombre) et `number` avec `TS_RS_LARGE_INT=number`.
- `cargo test` exporte les fichiers dans le dossier de `TS_RS_EXPORT_DIR`, avec l'en-tête « Do not edit this file manually ».
- Avec `ts-rs` en **dépendance de développement** et `#[cfg_attr(test, derive(ts_rs::TS))]`, la génération fonctionne et `ts-rs` n'apparaît pas dans l'arbre de dépendances normal.
- `cargo deny check bans sources` (avec le `deny.toml` du dépôt) passe.
- `tauri-specta` et `specta` n'ont que des versions 2.0.0-rc.25 (mai 2026) ; leurs dernières versions stables datent de 2023.

**Non vérifié.** `tauri-specta`, `typeshare`, `schemars` + outil npm (non essayés) ; Windows ; les types génériques.

## Options

1. **`ts-rs` 12.0.1, dépendance de développement (retenue).** Stable, simple, essayée.
2. **`tauri-specta` (release candidate).** Génère aussi les fonctions typées des commandes et sait décrire `Channel`, mais c'est une préversion dans la couche de sécurité du contrat, non essayée.
3. **`typeshare` ou `schemars` + `json-schema-to-typescript`.** Outil externe à installer et à épingler en CI (`typeshare`, gestion de `u64` non vérifiée) ou génération en deux étapes avec un paquet npm de plus ; aucun gain sur `ts-rs` pour ce besoin.

## Décision

**Option 1**, avec les règles suivantes.

- `ts-rs` (version 12.0.1 au moins, fonction `serde-compat`) est une **dépendance de développement** de `apps/desktop/src-tauri` seulement. Les crates du cœur n'importent ni `ts-rs` ni de type TypeScript.
- Les types échangés sont des **DTO** définis dans un module de `apps/desktop/src-tauri` ; ils convertissent les types du cœur. Ils dérivent `Serialize` (et `Deserialize` quand ils sont reçus) et, sous `#[cfg_attr(test, derive(ts_rs::TS))]` avec `#[cfg_attr(test, ts(export, export_to = "…"))]`, `TS`. Les unions utilisent une balise explicite (`#[serde(tag = "kind")]`), jamais un type libre.
- **Entiers.** `.cargo/config.toml` fixe `TS_RS_LARGE_INT = "number"` : les tailles en octets et les identifiants tiennent dans 2^53 (environ 9 pétaoctets). Aucun `i64` ni `u64` ne sert à un horodatage (RFC 3339 en texte) ni à une valeur qui pourrait dépasser 2^53.
- **Sortie.** `.cargo/config.toml` fixe `TS_RS_EXPORT_DIR` sur `apps/desktop/ui/src/lib/generated` (chemin relatif à la racine). `cargo test` génère un fichier par type, avec l'en-tête « Do not edit this file manually ». Le dossier est versionné.
- **Fraîcheur en CI.** Un contrôle du projet (`tools/extra-checks.sh`, point d'extension de `tools/run-checks.sh`, prévu pour les contrôles propres au projet) lance les tests de `breathly-desktop`, puis échoue si `git status --porcelain apps/desktop/ui/src/lib/generated` n'est pas vide (fichier modifié ou nouveau). Sonde négative décrite dans la PR : modifier un champ d'un DTO sans régénérer échoue `make check`.
- **Commandes.** Les signatures des commandes ne sont pas générées : `apps/desktop/ui/src/lib/api/` les écrit à la main avec les types générés (le seul endroit qui appelle `invoke`, `apps/desktop/ui/CODING.md` §1). Les types de `Channel` (ADR 0015) sont les types des messages.
- Prettier et ESLint ignorent le dossier `generated/`, qui reste soumis à `svelte-check`.

## Conséquences

- Le ticket #35 écrit la configuration (`.cargo/config.toml`), le premier DTO (l'erreur typée du contrat, #34), le contrôle de fraîcheur et la sonde négative.
- Les tickets de contrat (#37, #61, #86, #113) définissent leurs DTO dans leur PR.
- Un type du cœur jamais exposé n'a pas de DTO : l'ajout d'un champ au cœur ne change pas le contrat tant que le DTO ne le reprend pas.
- `ts-rs` n'est pas dans le binaire livré (dépendance de développement) : aucun coût pour les budgets de l'ADR 0008.
- Si `tauri-specta` atteint une version stable, un nouvel ADR pourra la comparer : le dossier `generated/` et les DTO restent des fichiers du projet.

## Impact sur l'architecture

Aucun changement du graphe de dépendances (design 0002 §3). Le design 0002 §6 (« crate de génération à choisir ») et §9 point 3 passent à « décidé » dans la PR du ticket #35. L'ADR 0012 n'est pas modifié : `ts-rs` s'y ajoute par cet ADR, avec sa version et sa date de publication (12.0.1, 2026-01-31).
